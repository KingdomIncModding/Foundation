# Foundation 0.8.0 — source upgrade and verification

This update edits the submitted **Foundation 0.7.1** sources, referencing the submitted decompiled **Kingdom Inc** sources. It does **not** replace BepInEx or the game's native flow simulation.

## Changes made

1. **Apply / Cancel bug** — `ModConfigToggle`, `ModConfigSlider` and `ModConfigDropdown` now maintain pending values. Editing controls does not write `ConfigEntry` fields or call external callbacks until Apply. Cancelling reads the getter again to restore the actual committed value. No-op commits do not invoke callbacks. A `BeginEdit` lifecycle refreshes values when the native Options panel is opened, but not when a different mod tab is rendered. Removing the duplicate Apply/Cancel `onClick` listeners means Harmony prefixes are the single path for commit/cancel. Hiding Options by any other route cancels staged edits.
2. **Read-only BepInEx dropdowns** — Replaced an invalid `IReadOnlyList<string>` to `IList<string>` cast with a count/index lookup. E.g., `Array.AsReadOnly(options)` now works.
3. **Native IO and pipe inspector** — Added `Api/FlowInspection.cs` containing `IFlowInspectionService`, `FlowElementSnapshot`, `FlowPortSnapshot`, `FlowPipeSnapshot` and `FlowPortDirection`. `FoundationApi.Flow` returns the service. The data is captured from native `FlowElement`, `FlowIO`, `FlowPipe`, and `FlowDiagram` types. Snapshot collections are read-only; the API is designed for inspection rather than mutation.
4. **Native pipe events** — Added `Plugin/FlowIntegration.cs` Harmony postfix for `FlowPipe.Connect` (non-ghost only), prefix/postfix for `FlowDiagram.DisconnectPipe`, and postfix for live `WorldFlowPipe.ItemTransferred` (successful item transfer). Listeners are exception-isolated. These events describe native callbacks and do not invent throughput-rate rules.
5. **Nexus API credential** — Removed the distributed fallback credential, requiring a user-supplied key if update checking is desired.
6. **Smoketests** — Extended `VerifyModConfig` and `VerifyWorkspaceRegistry` with staged value/cancel tests and direct read-only flow/pipe event checks. No fake simulation rules or custom frameworks were introduced.

## Compatibility

- Existing public interfaces and method signatures remain in place. The new inspector is additive.
- **Intentional behavior change:** `OnValueChanged` and `OnSelectionChanged` callbacks for built-in mod config controls now fire on **Apply**, not on each UI interaction. Mods depending on immediate side effects must move that behavior to an explicit immediate action or custom control.
- Buttons still execute immediately; Foundation cannot undo arbitrary button actions.
- Commit/cancel is staged per element, **not an all-or-nothing transaction across every callback**. A callback that throws is logged, and other elements still run.
- Any plugin that bundles old `Foundation.dll` should remove that DLL and depend on the player-installed Foundation. The example consumer's minimum dependency remains `0.7.1` for compatibility; it can run against `0.8.0`.
- This release does **not** implement arbitrary new signal IO, hot-reloading, missing-node recovery, or save schema migration. Those require dedicated designs and game runtime validation.

## Validate on your Windows Kingdom Inc installation

Place the revised Foundation source in its normal directory (`<KingdomInc>/_Mods/Foundation`). **Back up your working 0.7.1 version first.** Execute these commands in PowerShell with the game closed:

```powershell
dotnet build .\Foundation.csproj -c Release
dotnet build .\Examples\ExampleTechNodes\ExampleTechNodes.csproj -c Release
.\verify-isolated.ps1
.\verify-isolated.ps1 -WithExistingPlugins
```

Check `Verification/runtime-tests.json` and the Unity logs. If both smoke test passes succeed, use the existing `install.ps1 -WhenGameCloses` or package scripts. **Do not install an unbuilt `Foundation.dll` from the original upload**, because it is version 0.7.1 and does not contain these changes.

## Limits of this exported source update

The uploaded archives provide C# sources and previous build outputs but do **not** include Unity's managed libraries, the live `Assembly-CSharp.dll`, or the BepInEx/Harmony binaries that `Foundation.csproj` references. This environment has no .NET SDK or a running Kingdom Inc instance, so this revision is **not compiled or gameplay-tested** here. Compilation and isolated gameplay verification must be completed against your installed game.
